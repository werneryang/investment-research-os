# 产业链研究数据库与可计算模型：设计、数据可行性及实施方案

> 状态：**规划中（设计决策与实施建议，不代表已完成代码或数据接入）**  
> 讨论基线：2026-10-27；初始范围：美国市场与可免费取得的公开数据，必要时注明全球产业链缺口。  
> 定位：Investment Research OS 的跨方向研究能力，服务“地区与行业”“证券与基金”“组合与情景”，不另造一套与现有研究框架冲突的分类体系。  
> 设计基线：[架构](architecture.md) · [研究框架地图](research-map.md) · [实现说明](implementation.md) · [行业专题](study-industries.md) · [公司研究](study-companies.md)。

## 0. 研究目标与边界

目标不是把上市公司简单放进某个最细行业，而是建立**行业 → 细分业务/产品 → 公司业务 → 有证据的上下游关系**四层可追溯数据库，再用与事实层分离的计算模块研究：需求沿产业链怎样传导、哪些环节可能出现约束、哪些公司可能捕获经济价值、哪些结论因数据不足而不能做。

研究必须区分：①已经观察到的事实；②依据明确的模型计算得到的结果；③显式设定的情景假设；④缺数据、尚不能回答的问题。产业链网络不等于采购合同记录，经济关联不等于因果关系，需求上升不等于利润必然上升，更不等于股票回报。

**总体顺序：结构可追溯 → 数据可行性检查 → 可计算的局部模型 → 历史验证 → 价值捕获与投资研究。** 先证实可以取到真实、匹配口径的数据，再承诺模型能力。不要先建一个功能齐全却没有可靠输入的大型图数据库或网站。

## 1. 四层逻辑数据库（不是四套独立物理数据库）

| 层 | 核心对象 / 来源 | 核心问题 | 必须留下的边界 |
| --- | --- | --- | --- |
| **L1 标准行业** | NAICS（代码版本）、SEC SIC、BEA行业对应；GICS仅在许可允许时作辅助 | 经济活动属于哪个标准行业？ | NAICS以经营单位/主要活动为核心；SEC SIC常是申报主体标签；不能当成公司所有业务的完整分类 |
| **L2 细分活动与产品** | NAPCS、研究用业务/工艺词表，产品和单位 | 具体制造或提供什么？ | GPU设计、晶圆代工、HBM、先进封装、液冷等可能比六位NAICS更细；自定义标签不得冒称官方分类 |
| **L3 公司及其业务** | CIK/申报主体、10-K/10-Q分部披露、XBRL/原文、业务映射 | 哪家公司在哪些环节经营，披露了多少业务数据？ | 一家公司可有多项业务；分部收入不必然等于单个产品收入；须区分实体、分部、地区与财年 |
| **L4 产业链关系** | BEA行业投入产出；公司披露供应、客户、代工、合作与竞争关系 | 谁向谁提供哪种投入？哪些是间接依赖？ | BEA仅是行业汇总投入关系，**不能推导某两家公司确有采购**；关系必须有方向、类型、期间和证据 |

四层是逻辑分层，不要求新建四个独立数据库。公司与细分业务、活动与NAICS、公司与财务分部之间均允许**多对多**映射，且有各自的版本与有效时间；不能把一个公司强行压成唯一六位NAICS标签。

产业链图的边应具体到“上游活动/产品 → 下游活动/产品”或“供应主体 → 采购主体”，并区分已披露、来自汇总统计、推断、未知。竞争与可替代关系不是供应关系，必须用单独的关系类型。

## 2. 借鉴的研究方法：先分开，再按证据组合

| 方法 | 对应研究问题 | 第一版做法 | 限制与后续扩展 |
| --- | --- | --- | --- |
| **供应链知识图谱 / 多跳遍历** | 产品、公司和上下游如何连接，间接依赖在哪里？ | 关系表 + 有向图查询；每条边附证据 | NLP / RAG 可辅助提取候选边，但自动提取不自动确认为事实；多跳增加错误传播 |
| **Leontief投入产出分析** | 某行业最终需求变化，产生多少直接与间接行业总产出要求？ | 使用同年同口径BEA系数矩阵 A，在适用条件下计算 x=(I−A)⁻¹y | **货币口径**，反映平均行业结构；未自动考虑价格、进口替代、产能约束和具体企业采购 |
| **物理投入与约束优化** | 当产能不足时哪些环节限制产出？ | 首版固定BOM/投入系数的无环网络；有多个产品/供应商时才用线性规划 | 只有同一时期、单位和地区可比的投入/产能数据才能计算；不能用BEA美元系数直接代替“每台用几颗GPU” |
| **动态系统 / 库存与时滞** | 订单、库存、交期与扩产如何影响不同月份？ | 第二阶段起，显式增加库存流量、交货提前期与投资滞后 | 必须验证动态参数与初始状态，避免拟合故事 |
| **瓶颈、集中度、韧性分析** | 单点失败、替代性及产能冗余在哪里？ | 用已证实关系和可靠产能做局部敏感性分析 | 未知供应商不等于不存在；集中度须明确分母及覆盖 |
| **价值捕获 / 利润桥** | 需求增长后哪个环节更可能获得增量利润？ | 将量、价格、毛利率、资本开支与分部披露分开建模，先做区间情景 | 实际合同价、成本、替代品、议价能力往往缺失；不得把增加的产量直接等同利润或股价收益 |
| **历史时点验证 / 因果识别** | 模型事前有用吗？观察到的共同变化是否因果？ | 固定历史可知输入和基准策略，做样本外比较；因果研究另立识别设计 | 使用后来的披露、修订或公司关系会前视；相关性不能写成因果 |

架构原则：**事实数据库、模型定义、情景参数、输出与证据档案相互独立**。更换计算模型不应重写原始事实，新增AI提取工具也不得成为核心计算的必需依赖。

## 3. 免费数据资源：数据用途与真实接入状态

以下“官方公开可取”仅表明存在候选官方发布渠道，**不是**本项目已下载、已标准化、已核验相应用途。必须区分来源发现、实际取得、解析成功、按用途验证这四种状态；不能将文档中的数据源列表写成“系统已接入”。

| 来源与官方入口 | 适用层级与输入 | 潜在能力 | 对本产业链方案的当前核验状态 |
| --- | --- | --- | --- |
| [Census NAICS 2022](https://www.census.gov/naics/) / [2022手册](https://www.census.gov/naics/reference_files_tools/2022_NAICS_Manual.pdf) | L1六位行业目录、版本 | 行业骨架 | 资源已识别；产业链模块**未验证下载与交叉映射** |
| [Census NAPCS](https://www.census.gov/naics/napcs/) | L2产品/服务分类参考 | 细分产品词表 | 候选；**未验证公司产品映射** |
| [SEC SIC目录](https://www.sec.gov/search-filings/standard-industrial-classification-sic-code-list) | L1/L3申报公司初始标签 | 公司级粗分类 | SEC数据已用于仓库既有财报研究；**业务拆分映射未完成** |
| [SEC EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) / 10-K、10-Q原文 | L3公司财务、分部及供应链文字证据 | 实体、分部、财务、关系抽取 | 仓库已核验15家公司核心财务事实；**分部/客户/产能全覆盖未核验**，Company Facts不等于所有分部表 |
| [BEA投入产出表](https://www.bea.gov/data/industries/input-output-accounts-data) | L1/L4 行业投入与需求（金额口径） | 行业间需求传导与系数矩阵 | **候选，产业链IO下载/解析/系数核验未做**；与仓库已用BEA行业增加值是不同数据集 |
| [Census M3](https://www.census.gov/manufacturing/m3/currentdata.html) | 订单、出货、库存、未完成订单 | 较粗制造业环节动态 | 候选；**未做本研究用途核验**，并非每个NAICS六位行业都有序列 |
| [Federal Reserve G.17](https://www.federalreserve.gov/releases/g17/) | 工业生产、行业产能指数及利用率 | 行业景气、利用率约束/辅助校验 | 工业生产的部分数据已用于现有行业研究；**不能把指数当成芯片实物绝对产能** |
| [EIA石油数据](https://www.eia.gov/petroleum/data.php) / [炼油厂产能资料](https://www.eia.gov/petroleum/refinerycapacity/) | 炼油处理量、库存、产出、利用率、年度设施产能 | 真实行业量纲的约束模型优先样本 | 仓库有EIA WTI价格来源；**炼油吞吐量/设施产能管道尚未验证**，不能混同“EIA已接入” |
| [BLS QCEW](https://www.bls.gov/cew/) | 按NAICS就业、机构及工资 | 环节规模/结构交叉核验 | 部分BLS行业数据已用于仓库；**该新模型用途尚未核验** |
| [GICS方法](https://www.msci.com/indexes/index-resources/gics) | 上市股票市场行业比较 | 辅助证券视角 | 分类方法可参考；**完整公司映射、历史及再分发许可不视为免费** |

已知粒度限制：BEA年度投入产出表通常约71行业，详细基准表约402行业且不是每年完整发布；NAICS 2022版六位分类约1,012行业，但“目录细”不代表有完整上市公司产品映射。数据源的年度/版本粒度应以实际发布文件核实，并保存该次获取的元数据。

**明确的缺口**：全球GPU单品出货/产能、HBM与先进封装按客户产能、产品级BOM、精确企业采购份额与合同价，在上述美国官方免费资源中通常**没有可验证的完整表**。因此不能承诺“仅靠官方免费数据”对AI芯片供应链完成公司级精确物理模拟或盈利预测。跨国供应链必须把美国官方数据的地理覆盖限制显式显示。

免费访问不等于API无速率限制、不等于历史版本完整或允许任意再分发。接入前核对URL、发布日期、版本、下载条件、缓存限制、许可、地理覆盖和发布后修订方式。

## 4. 必须实施的 DATA FEASIBILITY GATE（数据可行性门槛）

**这项检查贯穿 L1–L4，作为每一个拟开展的研究能力的前置条件，不是增加第五个行业分类层。** 每个行业、活动、公司业务、关系和指标分别审查，不能给整个行业一个笼统“数据完整”的标签。

每条数据能力档案至少记录以下字段：

- 研究问题/计算用途及所需输入清单；来源ID、URL/申报编号、许可、是否免费可持续取得。
- 粒度：行业/活动/产品/公司/设施；地域：美国/某国/全球；时间：观察期、更新频率、发布日期、历史修订和可用时间。
- 单位/币种/价格基年、供给与需求口径、覆盖分母、缺失比例、连接的行业分类版本和映射歧义。
- 原始数据取得状态（仅发现／已保存字节／解析通过／用途核验通过）、原始证据位置、内容哈希、提取方法与复核者/自动测试。
- **分别评估财务数据完整度与生产运营数据完整度**；公司财报很完整不表示其产品产能或供应商数据完整。
- 对每个模型输入标注 observed（实测/申报）、derived（计算）、assumed（假设）、inferred（推断）、unknown（未知），不能默默把unknown补零、前值或AI估计。

数据接入状态与研究能力判定是两套不同概念：

| 研究能力判定 | 允许输出 | 处理方式 |
| --- | --- | --- |
| **A：有真实数据可计算** | 与输入范围严格一致的量化结果 | 所有关键输入已取得、单位一致、用途核验通过、有足够覆盖、可复现；仍须写明模型假设 |
| **B：明确假设下可模拟** | 带范围、假设、敏感性分析的**情景结果** | 缺少可观测关键参数时由用户/模型显式配置；任何输出不得称为真实预测或已观察事实 |
| **C：暂不能计算** | 分类、结构、证据、缺口报告 | 输入缺失、地理或口径不匹配、不可验证时禁止输出伪精确数字 |
| **尚未评估** | 只显示待核验清单 | 不预设为A、B或C；新行业默认从这里开始 |

**硬性关卡：** 一个研究要给出A类结果，所有关键输入必须具有可查来源和经验证的用途；若证据不足则降为B或C；研究不得让AI自动填充缺失的实测值；模型不得因某个行业样本完整就默认别的行业也完整。产品级建模必须具备可比的物理投入比例，金额口径BEA表不能直接充作工艺BOM。

建议每项能力生成机器可读的 feasibility manifest，包括 input_id、role、scope、required、source_status、availability、missing_reason、capability_class、decision_reason、reviewed_at；网站明确列出缺口而不是只显示一个综合评分。

## 5. 工程模块与数据契约（复用现有代码）

**不另建独立应用仓库。** 优先复用现有 src/investment_os 的数据取得、原始快照、版本/时点规则、质量检查、研究运行、verify、报告及归档机制；新能力按需要添加模块，而不是一开始迁移到Neo4j或强制所有输入采用DuckDB。

建议模块职责：

1. **分类与映射接入器**：NAICS/NAPCS/SEC/BEA crosswalk，版本化目录；原始文件不修改。
2. **业务与关系证据接入器**：10-K文字、实体、分部、产品、关系候选；AI抽取仅产生“待复核候选”。
3. **可行性检查器**：从研究定义的必需输入、地理/单位/时点与证据登记生成A/B/C/未评估判定，拒绝不合格计算。
4. **公共计算引擎**：物理量投入与约束、行业金额投入产出，分别实现并测试，不在同一个函数中暗中换算。
5. **情景与验证**：显式需求增长、替代率、产能上限、库存、价格等参数；固定模型版本和输入快照，生成离线回归测试及历史检验。
6. **成果层**：输出机器可读结果、方法、限制、不能回答的问题和证据链；网络图/网页为后续展示。

建议概念数据表（实际可映射到Parquet/DuckDB/现有注册与契约）：

| 数据对象 | 关键键与内容 |
| --- | --- |
| industry_codes / industry_crosswalks | system、code、edition、valid_from/to、映射权重/歧义、source_ref |
| activities / products | activity_id、product_id、名称、工艺节点、标准/自定义标签、单位 |
| entities / company_activities | CIK或稳定实体ID、ticker历史、activity_id、业务角色、有效期、披露引用、分部映射 |
| relationships | from_entity/activity、to_entity/activity、relation_type、产品、方向、证据级别、valid_from/to、source_ref |
| observations / capacities | metric、value、unit、geo、period、facility/activity、published_at、available_at、retrieved_at、version_id、evidence_id |
| input_requirements | 上游产品、下游产出、系数、单位、区域/年份、observed或assumed、evidence_id |
| evidence / provenance | source_id、URL、CIK、accession、页/章节/原文片段定位、raw_hash、取得时间、许可 |
| feasibility_assessments | study/capability、required_inputs、source_status、A/B/C/未评估、理由、阻断项、日期 |
| scenario_runs / outputs | scenario_id、参数快照、模型/代码版本、输入版本、结果、缺口、可复现清单 |

避免模型偷换的关键是：
- 每个 observation/relationship 必须区分 **事实有效期** 与 **首次公开或本系统可知时间**；无法证明时点可用时，不得纳入历史 as-of 回测。
- 区分 product/material 的物理数量（件、桶/日）与BEA的美元投入比率；跨口径需明示独立的价格与单位转换数据。
- “未知关系”不同于“无关系”；“产能利用率”不同于“绝对可生产产品数”；不同设施和产品的产能不可未经换算直接相加。
- 图上的 inferred 边只能用于探索或标明假设的B类模型，不得冒充公司披露关系。

## 6. 可验证的最小实现（MVP）与实施顺序

**P0 — 数据可行性盘点（先于正式开发）**

选择两个对照样本：美国炼油链（EIA物理数据相对充分）与AI半导体/数据中心链（全球和公司级关键输入缺口较大）。针对至少各5个核心指标，逐项填：是否免费、是否真的下载成功、单位与期间、地域、历史版本、是否足以支撑具体计算、A/B/C/未评估。输出 source inventory、feasibility manifest 和阻断清单。**这是启动任何模拟的前置验收。**

**P1 — 建最小事实模型**

建立少量可版本化活动、产品、公司、关系及来源对象；用3–5个生产环节/5–10个实体的可审计小样本验证多对多映射、证据链接、有效期和时点查询。禁止凭分类代码自动生成公司采购边。所有新结构要有 schema_version 和从旧版本迁移或拒绝策略。

**P2 — 先用离线虚构数据验证计算器**

测试用例：AI服务器年度需求700台，每台4颗GPU；GPU能力3,600颗，封装能力3,000颗，需求上升20%。理论需求840台、GPU需求3,360颗、封装最多支持750台、缺口90台。**全部是虚构的单期测试值，不代表实际芯片产业链。** 检查无瓶颈、单瓶颈、多个瓶颈、单位不一致、缺失输入、替代品、回路被拒绝等边界；首版可限定无环、固定物料投入比。

**P3 — 用EIA真实数据跑通“取得→核验→模拟→报告”**

实际下载美国炼油行业的历史周度投入/利用率和年度可运行产能数据，按地域、时间、单位一致性归一化；反算利用率与EIA公布值在舍入误差内一致后，开展需求+5%、+10%、+20%等**约束情景**。必须记录所用产能定义、停机/维护、进口与库存不在单期模型内等限制。此阶段验证计算平台而非证明未来预测准确。

**P4 — 用BEA行业投入产出表做第二类模型**

实际下载相应年份投入产出及行业映射，验证行业行列、单位、总计与系数，构建金额口径行业需求传导；严禁与P3物理产能无证据地直接拼接。可分析行业聚合层面的直接/间接需求，但不写成公司之间真实采购关系。

**P5 — 上市公司业务与证据连接**

选择10–15家代表性上市公司，用SEC申报将公司多业务与活动词表映射，并区分“披露确认/研究推断/尚未知”。只在有可信分部资料时关联财务，记录无法归属的比例，给每条供应关系留原文定位与有效时间。GPU/封装缺精确实物系数时保持C（结构可看、不能精确模拟），或使用显式假设提供B类演示。

**P6 — 进阶模型与展示（达到前置标准后）**

引入多产品多供应商线性规划、库存与时滞、替代性/弹性、价格与利润桥；用预先固定的时间窗与基准做样本外评价。最后生成可交互的产业网络与情景图，支持点击指标查来源、能力等级和不能回答的内容。

以上为依赖顺序，不预设工期。各阶段运行数据的保存与公开再分发要遵守原项目的许可、快照和archive规则。

## 7. 验收标准（成功的含义及拒绝发布条件）

| 维度 | 最低验收 |
| --- | --- |
| 数据真实性 | 每个用于正式研究的关键数值都能追到官方原始文件/申报、具体期间和单位；原始字节与内容哈希保存 |
| 来源用途核验 | 来源存在 ≠ 取得成功 ≠ 已解析 ≠ 此研究用途可用；研究清单逐项显示状态，未过门槛拒绝A类计算 |
| 逻辑完整性 | 公司可对应多个活动；关系方向/类型正确；每条重要边有证据或显式“推断/未知” |
| 数值正确性 | 虚构样本有独立预期值；EIA利用率与官方公布值在规定的舍入范围一致；BEA行列及平衡检查通过 |
| 单位与范围 | 错单位/错国家/错年份不能静默混合；货币投入系数与物理物料比率分开 |
| 时间正确性 | 历史时点查询排除后来才知道的关系、修订值和披露；未知发布时间的资料在时点研究中拒绝 |
| 缺失处理 | 缺关键输入自动阻断或降级到B/C；绝不由AI静默填缺；显示研究无法支持的结论 |
| 可复现 | 同一固定输入版本、情景和代码重算结果相同；verify核对文件完整性与模型版本 |
| 经济解释边界 | 需求传导不等于因果；产能瓶颈不等于真实交期；估值/利润结果须另有披露与假设支撑 |
| 产品完成 | 至少完成一条真实官方数据链的数据下载、标准化、核验、情景计算、结果与证据报告；没有做到不能写“生产可用” |

建议最小演示输出：scenario.json（假设）、results.csv或Parquet（逐环节数值与单位）、evidence.json（来源与输入版本）、feasibility.json（每项能力的A/B/C及阻断理由）、report.html（解释与限制）、run manifest（哈希/代码版本）。

## 8. 重要注意事项与暂不承诺事项（未来实施时必须重新审查）

1. **数据可行性检查是一项硬约束**：每次扩展新行业或新模型都重跑，并分开记录行业/财务数据与产品/运营数据的完整度；部分行业更完备不代表全部行业可用。
2. **NAICS、SIC、GICS、NAPCS、BEA的分类粒度与研究目的不同**：跨表映射可能是一对多、有损或随版本变化；不允许未经证据的“自动精确对齐”。
3. **BEA金额投入产出系数不是产品制造工艺BOM**；402行业详细表的年份与年度71行业不等同；预测需求响应还受价格、替代、进口与产能约束。
4. **美国上市公司 ≠ 美国生产地点**；海外代工、跨国分部、生产设施与法律申报主体要分开建模。
5. **真实产能往往是区间和条件性的**；EIA炼油数据虽可用于工程验证，也不能将某周公布值当作永久不变的硬上限。
6. **SEC完整公司财务不等于精确业务/客户/供应链**；未披露的客户合同、GPU型号出货、先进封装细节不能由文本概率猜测补成正式数据。
7. **AI抽取只辅助候选发现**，必须保存原文定位和人工/规则验证；混淆、实体重名、供应商变更与跨年关系都会导致错误。
8. **历史不能偷看未来**：披露和修订时点、来源真实可知时间、模型训练/选参窗口必须冻结；报告中注明复现与预测有效性不是一回事。
9. **许可证、抓取速率、存储与公开分享须单独确认**；官网可读或免费可下载并不自动代表可以把数据全量上传到GitHub Pages。
10. **本设计为规划**：上述EIA炼油原始指标、NAICS/NAPCS/BEA IO映射和新模拟引擎尚未在仓库执行端到端验证，不应从本文件推断它们“已经接入”。
