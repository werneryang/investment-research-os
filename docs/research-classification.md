# 研究分类映射（实施依据，2026-10-31）

> 状态：配对分类、双向目录、章节锚点及参照入口已在网站生成器实现；架构 §4、研究框架地图与网站登记同步迁移。部署结果以对应 GitHub Actions 工作流为准。研究计算与原始证据状态不因导航迁移而改变。

目标：用户知道自己要研究什么，就能沿稳定路径找到**真正回答该问题的内容**，并清楚看到尚不能回答的部分。

本文先逐项登记现有研究实际回答什么（§3），再用常见查找任务检验（§5）。分类依据是研究定义的 `question`、`result_type`、`limitations` 与研究页实际展示的内容，不按标题或印象归类。

## 1. 分类原则

1. **两条轴，双向进入。** 「研究对象」说明研究谁，「研究问题」说明研究它的哪方面。用户可以先选对象再选问题，也可以先选问题再选对象；两条路径查询同一份登记，不维护两套内容。
2. **一份记录，一个主归属，多个检索入口。** 每项研究只有一个研究页地址。主归属（对象 + 问题）用于默认目录与统计；其他问题与对象作为有效检索入口，从那里进入时直接列出该研究并指向对应内容。结果列表按研究去重。
3. **只收实际提供的结果。** 一项研究进入某个问题子类，必须在结果中提供该子类要求的输出（§2.2 的纳入条件）。提到某个概念、或数据集里有相关字段，都不算。
4. **问题类型与成果类型分开。** 研究问题说明研究什么；`result_type`（描述与比较、解释与归因、情景模拟、预测）说明成果的性质与验证要求，作为筛选条件，二者不互相代替。
5. **研究与参照资料分开。** 来源目录、行业分类、产业链映射与关系是参照资料，不是研究结果；它们有自己的确定程度（§4），不因放在同一入口而显得已经确定。
6. **默认目录不铺开未评估的空格子，主动查询必须解释空结果。** 只按有依据的对象、问题与范围登记已有研究、已有数据尚无研究、规划中、不适用。未登记的组合默认尚未评估；主动查询时根据实际匹配记录区分：当前结果可用、研究已登记但内容未发布/缺失、已有部分参照、已有数据或规划、被附加条件筛掉，以及没有登记而尚未评估。缺口说明来自登记与核查，不由数据接入或一条规划扩展到整个对象类别。
7. **按对应关系登记，按当前输出展示。** 每条入口绑定「对象及子类 + 问题及子类 + 内容位置 + 适用范围」，其中一条为主归属；禁止将对象列表与问题列表自动交叉组合。静态登记表示预期能力，当前运行实际输出且可访问的内容才算可用结果。背景链接、证据链接与直接回答问题的入口分别处理。

## 2. 词表

### 2.1 研究对象

| 对象 | 子类 | 说明 |
|---|---|---|
| 宏观经济 | 通胀；政策利率与流动性；增长与就业 | 宏观变量本身是研究对象时才归入；只作背景或其他研究的分解项（如通胀补偿）不算 |
| 大类资产 | 股票市场整体；国债与利率；信用；房地产；黄金与商品；多资产比较 | 资产类别层面的价格、收益率与回报 |
| 行业与产业链 | 行业组合（French 12/49 等）；细分产业（炼油、芯片等） | 行业或产业整体；细分产业按经营活动定义，不冒充官方分类 |
| 公司 | 经营主体 | 公司财务、分部与经营 |
| 证券 | 具体证券（真实债券、个股） | 具体证券的价格、现金流与股东总收益；假设债券不属此类 |
| 基金 | 基金产品 | 费用、持仓、净值 |
| 组合 | 构造的组合 | 只收实际构造了权重或组合的研究；资产间相关性本身不算组合研究 |

「公司、证券与基金」在导航上可以暂时合为一个大类，但登记时分开，避免公司财务、证券定价与基金费用混在一起。

### 2.2 研究问题与纳入条件

| 问题 | 子类 | 纳入条件 | 不纳入 |
|---|---|---|---|
| 收益与风险 | 历史回报（名义/实际）；波动与回撤；相关性；压力时期表现；超额回报 | 输出持有期或总收益，或基于这些收益的风险、相关性统计 | 收益率水平（见下一行） |
| 价格、收益率与价差 | 价格与指标水平；收益率曲线形态（水平、斜率、曲率）；价差水平（信用利差、裂解价差） | 输出价格、收益率、价差或市场指标的水平与变化 | 持有期回报 |
| 估值 | 估值倍数快照；估值背景指标；现金流估值；隐含预期回报 | 输出价格相对盈利、账面价值或现金流的比率，或由模型得出的价值 | 历史回报之差（如历史股票风险溢价）；只有财务数据没有价格 |
| 基本面与经营 | 经济指标；财务指标；分部经营；实体行业产出；产能与利用率；管理层指引对照；产品费用 | 输出经济、财务、经营、产出或产品费用的数值与变化 | — |
| 结构与关联 | 分类与业务构成；产业与公司关系；集中度与样本构成；持仓构成 | 研究结果中输出结构或关系 | 只在参照资料中登记的关系（见 §4） |
| 暴露与关联 | 因子暴露；宏观环境分组表现；领先/滞后相关；指标间的历史关系 | 输出统计暴露或历史关联，并声明不作因果解释 | — |
| 分解与归因 | 会计恒等式分解；模型归因；因果识别 | `result_type` 为 explanatory，写明恒等式或模型 | 描述性关联（归入上一行） |
| 情景与敏感性 | 利率冲击；产能或处理量情景；压力情景 | 输出假设条件下的计算结果，假设写明 | 历史压力时期统计（归入收益与风险） |
| 预测与信号 | 预测准确性；信号有效性；策略模拟表现 | 有基准、时间可得性与样本外检验 | — |
| 数据可得性与口径 | 覆盖与口径核对；可比性分析；免费数据能否回答某问题 | 研究问题本身就是数据能否支持结论或对象能否比较 | 每项研究都有的覆盖说明 |

「暴露与关联」和「分解与归因」分开，是为了不把描述性的关联升级成解释。「数据可得性与口径」保留为面向读者的问题类型；普通覆盖检查、申报版本和修订候选通过证据链接访问，不增加「证据」问题类别。

### 2.3 筛选条件（两条路径共用）

| 条件 | 来源 | 说明 |
|---|---|---|
| 成果类型 | 研究定义 `result_type` | 已有 |
| 市场 | 研究定义 `scope.market` | 目前全部为 US。指上市或数据覆盖市场，不代表公司注册地、经营地或收入敞口；需要区分时再增加字段 |
| 期间 | `scope.start` / `scope.end` | 滚动窗口（如「最近一年」）按运行时实际期间显示 |
| 频率 | `scope.frequency` 或数据集频率 | — |
| 数据截止 | 运行结果 `data_cutoff` | — |

| 大类资产 · 股票市场整体 × 价格、收益率与价差 · 价格与指标水平 | 已接入 VIX，尚无对应研究 | `vol_premium`；VIX 水平不等于已实现波动率或波动率溢价研究 |
| 大类资产 · 多资产比较 × 收益与风险 · 历史回报 | 跨市场范围已有数据，尚无对应跨市场研究 | `global_assets` 的地区因子收益；美国多资产历史研究已经存在，必须保留范围限定 |
| 基金 × 基本面与经营 · 产品费用；基金 × 结构与关联 · 持仓构成 | 规划中 | `fund_costs.needs`，拆为两条对应关系 |
| 证券 · 真实债券 × 收益与风险 · 历史回报；基金 · 债券基金 × 收益与风险 · 历史回报 | 规划中 | `real_bonds.needs` 的现金流、价格与总收益缺口，按对象拆分 |
| 行业与产业链 · 芯片 × 结构与关联 · 产业与公司关系 | 有本地候选参照记录，尚无已发布的关系研究 | §4，不扩展到所有行业；参照记录不计入研究数 |
| 公司 × 估值 | 尚未评估 | 主动查询时明确无已发布研究及未评估状态，不自动编写缺口原因 |

`signal_tests` 只登记了通用的信号与预测检验规划，尚未限定对象，不生成“各对象 × 预测与信号”的规划格子。它保留为待分配的能力规划，落实具体对象、目标与范围后再登记对应关系。

## 4. 数据与参照资料

参照资料与研究共用「数据与参照」入口，按同样的研究对象浏览，但各自写明确定程度。

| 资料 | 内容 | 确定程度 | 现状 |
|---|---|---|---|
| 来源目录 | 数据来自哪里、许可、核验状态 | 按「来源 × 数据集 × 用途」的核验记录 | 已发布（`sources.html`） |
| 标准分类 | NAICS 2022 结构表 | 官方来源，本地版本有校验值 | 不复制完整表，提供官方入口 |
| 细分业务 | 8 项芯片经营活动的定义、包含、不包含与候选 NAICS 对应 | 研究定义（v1）；NAICS 对应全部为候选 | 数据与参照页，按当前登记显示 |
| 分部事实及业务证据 | NVIDIA、Micron 的分部营收、营业利润及业务说明 | 27 条证据（含文字与数值证据）登记了机器核对与技术复核 | 进入芯片证据包与结果；无专用研究页正文展示，访问范围见 §3.4 |
| 分部与业务的映射 | 7 条（如 NVIDIA 计算与网络分部 → 芯片设计） | 7 条通过技术复核，全部为部分对应（partial），现实有效期未登记；不能用于收入分摊或确定历史时点归属，不等于人工确认 | 数据与参照页，按当前登记显示 |
| 公司间关系 | 17 条：供应 6、竞争 6、代工生产 3、晶圆代工 2 | 17 条均为候选（尚无技术复核）；只有一方披露的关系照写 | 数据与参照页，按当前登记显示 |

关系与映射发布时，每条显示类型、方向、适用范围、有效期（未知照写）、证据链接与技术/人工复核状态，候选不能显示得和已复核一样确定。复核有效性按当前内容指纹检查，历史复核记录不能覆盖后来改变的内容。公司页可以有统一的「分部与业务关联」栏目，没有收录的公司写「尚未收录」，不为统一结构而补资料。

## 6. 已确定的设计与实施顺序

以下决定已经落实于目录、渲染层和登记。

1. **保留 10 类问题。** 不为减少数量而合并收益率与回报、相关性与归因；补齐 §2 的子类以覆盖映射。界面按对象与范围展示相关类别，无须铺开完整矩阵。所有入口引用词表，背景与证据链接不得冒充问题分类。
2. **保留「数据可得性与口径」检索入口。** 仅纳入专门回答数据能力、口径或可比性的问题；普通检查与申报证据仍在证据面板，不能使每项研究自动命中这一类。
3. **行业专题主归属确定为基本面与经营。** 收益、估值、暴露等已有结果分别保留对应入口；主归属不限制其他有效查找路径。
4. **章节 ID 由渲染层定义。** 共同章节和专属内容区块分别定义稳定 ID，中英文相同，不由显示标题自动生成。映射引用这些 ID，构建检查目标存在且唯一；多个时期的区块须明确范围，不能重复 ID。定位折叠内容时须让目标可见。没有正文的研究可指向确已发布的完整报告并标注内容形式，不伪造章节。
5. **框架文档随分类迁移同步更新。** 架构 §4 将说明对象、问题、成果类型及横向筛选的职责；组合保留为对象，情景和预测跨对象使用，地区按真实含义筛选。保留既有研究边界，不改变计算实现中的 `branch`。已同步研究框架地图与网站登记。
6. **网站登记采用单一来源。** 词表和分类关系放在 `site/content.yaml`；每项研究的 `studies.<id>` 下保存「对象及子类、问题及子类、内容目标、适用范围」对应关系，其中恰好一条为主归属。不能分别保存对象数组和问题数组再交叉组合。旧 `primary_direction` 迁移或由新关系派生，不长期维护第二套归属；`collections` 保留为独立分组。成果类型、期间、实际结果和核验事实仍读取研究定义与运行记录，不在网站配置中重复维护。

实现分工：对应关系与词表在 `content.yaml`；内容目标与可用条件在 `targets.py`；双向目录与状态由 `discovery.py` 生成；参照由 `references.py` 发布。现有研究稳定地址保留，不因导航改版复制研究。

构建验收：30 项研究定义均有映射或明确的未发布状态；词表有效、主归属唯一；对应关系没有跨对象误配；当前运行确有声称的结果；中英文链接和章节均可访问；每份查询结果按研究 ID 去重；背景、参照、研究成果及证据状态分别表述。状态限定在具体对象、问题和范围内，可选数据缺失时不能继续显示该结果可用。


### 覆盖检查的落实（2026-10-31）

- `classification.references` 按资料登记稳定 ID、标题、原记录类型与 ID、目标章节及多个成对入口。同一资料只计一次，8 条活动定义、7 条映射和 17 条关系仍由原始登记提供事实。原记录 ID 只限定资料范围，不复制事实或复核状态。
- `navigation_coverage.py` 从公开参照记录反查导航归属。未分配的记录、无效引用或重复归属使构建失败；新增产业资料需明确所属资料与入口，不能自动混入芯片分类。
- `tests/test_navigation_coverage.py` 用独立的读者任务预期核对 30 项研究、10 项数据/规划和参照路径。测试生产筛选函数 `discovery-query.js`，逐一验证 18 个对象子类 × 39 个问题子类（702 个组合），中英文各一次，并覆盖父级筛选、主体限制与负例。组合遍历检查查询一致性，不表示这些组合都有研究或已完成领域评估。
- 截图中的芯片分类路径必须返回两份参照；公司估值、炼油未登记的产业关系、未知主体不能误命中。NVIDIA 和 TSMC 的匹配范围由明确记录决定，不能按名字猜测。
- 日期、市场、频率和成果类型仅过滤研究，参照与规划继续按对象、问题、主体、关键词匹配，界面说明其适用范围。没有这些属性的资料不会被无提示地全部隐藏。
- 中英文主页、能力地图使用同一模型，构建验证稳定锚点存在且唯一。`summary.json.classification.coverage` 输出已登记组合及研究/资料 ID 清单，供排查；不把未登记组合写成“已验证无研究”。

新增内容时，既要登记真实范围与入口，也要在独立查找任务测试中补充合理预期。纯组合遍历无法替代语义核对，不能仅因为测试通过就声称框架已经覆盖全部投资问题。
