# 事件研究：事件事实与时间线（第一版已实现，2026-11-15）

对应研究分类「事件与反应 · 事件事实与时间线」（[研究分类映射 §2.2](research-classification.md#22-研究问题与纳入条件)）。首例是 NVIDIA 首席执行官离任（`event_nvda_ceo_transition_2026`）。

## 1. 回答什么

一个有日期的具体事件发生后，公司申报原文写明了哪些事实、按什么顺序发生、何时披露；原文没有写明什么；截至查阅日公司公布了哪些后续日程。

不回答：事件原因、对经营或股价的影响、市场反应（属于「事件窗口的价格反应」子类，需要日度个股价格，尚未接入）。

## 2. 流程

```bash
uv run iros event fetch
```

```bash
uv run iros event bundle
```

```bash
uv run iros run config/studies/event_nvda_ceo_transition_2026.yaml
```

| 步骤 | 做什么 | 在哪里 |
| --- | --- | --- |
| 1 核实 | 在 EDGAR 申报列表找到含第 5.02 项（高管与董事变动）等事项的 8-K，确认事件确实发生 | 人工，结果写进登记的 `filings_checked` |
| 2 登记 | 每条事实写日期、类别、中英文陈述和原文逐字摘录；原文没写的事项写成 `not_mentioned`，附检索词 | `config/events/<event_id>.yaml` |
| 3 取得原文 | 下载登记的原文；年报等已在产业链登记的原文直接引用 | `iros event fetch`，存于 `data/events/filings/`（不入库） |
| 4 核对 | 原文 SHA256 一致；摘录逐字出现在原文中；检索词确实不在原文中；日程晚于查阅日 | `iros event check` |
| 5 证据包 | 核对零错误才生成，导入 `event_evidence` | `iros event bundle` |
| 6 研究 | 按日期排成时间线，算事件后的披露时滞，列出未提及事项和后续日程 | 分支 `event_timeline` |

事实类别：`context` 事件前的状态，`related` 同期其他变动（原文没说与本事件有关），`event` 事件本身，`scheduled` 已公布、尚未发生的日程。原文接受时间另列为「披露」。

## 3. 口径

- **只用公司申报原文。** 8-K、其附件（新闻稿）与年报。媒体报道、访谈不进时间线；需要时另行登记为外部来源，不与原文混在一起。
- **日期。** 事实日期取原文写明的日期；新闻稿中的事实取新闻稿日期。披露日取原文在 EDGAR 的接受时间，按美东时间计日。相对事件日按日历日计算。
- **原文未提及。** 列出检查过的原文和检索词，核对时确认检索词不在原文中。这只说明原文没有写，不说明事情不存在。检索词要避开原文中必然出现的词（例如第 5.02 项标题里的 Compensatory）。
- **更新。** 查阅日之后有新申报（继任者任命、10-Q 中的说明），在登记里加事实、改 `as_of` 后重跑；日程到期后按实际发生的情况登记。

## 4. 与其他仓库的分工

本仓库只放原文写明的事实和可复现的计算。事件的影响、原因的推测和个人判断写到 company-dossiers；找分析方法在方法库（research-method-extraction）的会话里按它的「突发事件」路径查。

## 5. 首例的范围与限制

- 事件日 2026-11-11，查阅日 2026-11-15，2026-11-26 更新（回任）。原文：8-K 0001045810-26-000082 及附件 99.1、8-K 0001045810-26-000060、2026 财年 10-K；更新时加入 8-K 0001045810-26-000090 及附件 99.1（回任）、8-K 0001045810-26-000088 第 2.02 项（原登记日程 11-17 已按时发生）。
- 回任作为同一事件登记里的新事实，事件日仍是离任日 2026-11-11；首份披露的时滞按离任计算。
- 2026 年 6 至 7 月的全球销售负责人更替列为同期其他高管变动，原文没有说明它与本次离任有关。
- 研究定义中的限制见 `config/studies/event_nvda_ceo_transition_2026.yaml`。
