# 个人投资分析框架：总体架构

Oct 22, 2026 · @Michael

## 设计目标与原则

这个框架要做到一件事：只用免费、可验证的资源，支撑一个覆盖美国、中国和全球市场的个人长期配置决策流程，并能从电子表格逐步升级到自动化代码管道。它是一个骨架，后续每一层都可以单独细化，而不需要推倒重来。

**前提假设（可修改）**

- 本币为美元，另保留人民币视角作为可选口径。
- 投资期限 10 年以上，以 ETF 和指数为核心，少量个股作为卫星仓位。
- 不做高频或日内交易，分析节奏以月、季、年为主。
- 有基本编程能力，因此每层同时给出"表格版"和"代码版"两种实现。

**五条设计原则**

1. **免费且可持续**：关键路径只用官方或长期稳定的免费来源；付费源和不稳定的非官方接口只能作为便利或备用。
2. **可靠**：每个关键数据至少有两个来源；官方来源优先；保存原始快照和抓取时间。
3. **可扩展**：分层解耦；新增资产、数据源或分析模块时只改注册表或增加插件，不改核心逻辑。
4. **可复现**：代码和配置用 Git 管理；任何结论都能从原始数据重新算出来。
5. **决策导向**：每个模块必须对应一个具体决策（配置、再平衡、买入、卖出）；不服务决策的指标不收集。

## 总体架构

框架分为六层：IPS 定规则，数据和存储层提供可信的输入，七个分析模块产出建议，决策层把建议变成有纪律的操作，复盘层把结果反馈回去修正假设。

左侧虚线是 IPS 对分析模块和决策的约束；右侧实线是复盘结果每季修正分析假设、每年复审 IPS。M1 只影响战术信号 M4，M2 只影响战略配置 M3，宏观判断不会直接改变长期配置。

## L0 投资政策书（IPS）

IPS 是整个框架的约束源：后面所有模块的输出，都要先通过这一页的检查。它应控制在一页以内，每年复审一次，只有生活状况变化时才修改。

| 项目 | 需要写清楚的内容 | 示例（待替换为你自己的数字） |
| --- | --- | --- |
| 目标 | 实际收益目标、资金用途和时间点 | 通胀 + 3%，用于 15 年后的退休储备 |
| 风险承受 | 可接受的最大回撤，以及回撤时的行动 | 组合回撤 25% 以内不改变策略 |
| 期限与流动性 | 资金多久不用；应急资金单独存放 | 6 个月支出放在货币基金，不计入组合 |
| 税务与账户 | 各账户类型，以及资产放在哪个账户 | 高分红和债券优先放在递延税账户 |
| 基准 | 用来衡量自己是否增值的被动组合 | 全球股票 / 美国综合债券 60/40 |
| 投资范围 | 允许和禁止的品种 | 禁止杠杆 ETF 和裸卖期权 |
| 集中度限制 | 单一持仓、单一国家、单一主题的上限 | 单一个股不超过组合 5% |
| 再平衡规则 | 触发条件和执行方式 | 偏离目标 ±5 个百分点，或每年一次 |
| 复审 | 何时、因为什么修改 IPS | 每年 1 月，或收入、家庭结构变化时 |

表格版：一个文档或表格页即可。代码版：写成 `ips.yaml`，供风险监控模块自动检查约束。

## L1 数据层：免费数据源清单

关键数据一律以官方一手来源为主、第三方为备；免费的行情类数据没有官方接口，是整个框架最薄弱的一环，必须有备用源和本地缓存。

**可靠性分级**

- **A 官方一手**：统计局、央行、财政部、交易所、监管申报。可作为唯一来源。
- **B 权威机构或学术**：指数公司、ETF 发行商、知名学者数据集、机构 CMA。可作为主来源，定期抽查。
- **C 稳定的第三方**：有明确免费额度或积分规则的平台。只作备用或便利层。
- **D 非官方抓取库**：通过抓取网页获取数据的开源库。只作便利层，不能是任何关键数据的唯一来源。

## L2 存储与工程层

存储层的核心规则只有一条：原始数据只追加、不修改，所有分析都从原始快照重新计算。这样任何一个数字出错，都能追溯到是哪一天、从哪个来源抓到的。

**表格版（起步）**：一个工作簿，分为资产注册表、持仓、交易记录、CMA、监控五个工作表。行情函数（如 GOOGLEFINANCE）只作便利，关键数字手工从 A、B 级来源录入并注明日期。

**代码版（升级）**：Python + Jupyter 做分析，Parquet 文件存数据，DuckDB 做单文件查询库，Git 管理代码和配置。全部免费，单机即可运行。

```text
invest/
├── config/
│   ├── ips.yaml          # 投资政策书：目标、约束、再平衡规则
│   ├── assets.yaml       # 资产注册表：代码、类别、市场、币种、基准
│   └── sources.yaml      # 数据源注册表：主源、备用源、等级、频率
├── adapters/             # 每个数据源一个适配器，统一输出格式
├── data/
│   ├── raw/              # 原始快照：来源/序列/抓取日期，只追加
│   ├── clean/            # 清洗后的统一长表
│   └── warehouse.duckdb
├── modules/              # 分析模块 M1–M7
├── checks/               # 数据校验规则
├── reports/              # 月报、季报、年度 CMA
└── journal/              # 决策日志
```

**统一数据格式**：所有序列转换为一张长表，字段为 日期、序列编号、数值、单位、来源、抓取时间、数据版本。宏观数据会被修订，因此要保留"数据版本"，避免用修订后的数据回测当时的决策。

**数据校验（每次更新自动运行）**

- 缺失检查：应有的日期没有数据。
- 跳变检查：单日变化超过历史波动的若干倍。
- 主备源比对：同一序列两个来源偏差超过阈值时报警，不自动选择。
- 口径检查：复权方式、币种、单位与注册表一致。

**安全与备份**

- API key 放在本地 `.env` 文件，不提交到 Git。
- 持仓和交易记录只放在本地或私有仓库。
- 原始数据按"本地 + 外部硬盘 + 云端"三份备份。

## L3 分析模块

七个模块各自回答一个决策问题，彼此只通过标准化的输出表交换信息，因此可以单独替换或升级。起步阶段只需要 M2、M3、M6 三个模块就能运转；其余模块按需加入。

| 模块 | 回答的决策问题 | 主要输入 | 输出 | 免费工具 | 频率 |
| --- | --- | --- | --- | --- | --- |
| M1 宏观体制 | 现在处于增长与通胀的哪个象限？政策在收紧还是放松？ | FRED、统计局、央行、收益率曲线 | 体制标签及判断依据 | pandas | 月 |
| M2 资本市场假设 | 各资产未来 10 年的预期收益、波动和相关性是多少？ | 收益率、TIPS 实际利率、CAPE、隐含 ERP、股息率、中证估值 | 区间形式的 CMA 表，以及与机构 CMA 的差异 | 积木法表格，或 Python | 年度更新，季度检查 |
| M3 战略配置 | 长期目标权重和允许的偏离带是多少？ | M2 输出、IPS 约束 | 目标权重、偏离带、敏感性分析 | PyPortfolioOpt、Riskfolio-Lib；Portfolio Visualizer 免费版（资产数和历史长度受限，见[来源](https://www.findmymoat.com/vs/curvo-backtest-vs-portfolio-visualizer)） | 年 |
| M4 战术信号 | 是否在偏离带内调整？调多少？ | 估值分位、趋势、信用利差、VIX、M1 输出 | 每类资产的低配、中性、超配信号，有上限 | pandas | 月 |
| M5 标的选择 | 用哪只 ETF 或哪只股票来实现配置？ | ETF 费用、跟踪误差、规模、流动性；SEC EDGAR、巨潮财报 | 候选清单、选择理由、证伪条件 | 发行商官网、EDGAR、巨潮 | 按需 |
| M6 风险监控 | 当前组合是否违反 IPS？风险集中在哪里？ | 持仓、价格、IPS | 权重偏离、回撤、波动、相关性、集中度、汇率暴露、压力测试 | pandas、quantstats | 月；触发条件下每周 |
| M7 复盘归因 | 收益来自配置、选择、时机还是运气？ | 交易记录、基准、因子收益 | 归因结果、因子回归、决策日志评分 | statsmodels、Kenneth French 因子数据 | 季、年 |

**模块之间的数据流**：M1 只输入 M4，不直接改变长期配置；M2 输入 M3；M3 和 M4 合成目标权重，交给决策层；M6 以 IPS 为检查标准；M7 的结论反馈到 M2 和 M4，用于修正假设。

**跨市场注意**：美国税务居民持有在美国以外注册的基金，可能涉及特殊的税务申报规则。M5 选择中国或其他非美国资产时，应把基金注册地作为筛选字段，具体处理需咨询税务专业人士。

## L4 决策与执行

框架只产生建议，交易由你在券商手动执行；每一笔非例行交易都必须先通过检查清单，并写入决策日志。这一层的目的是把"分析结论"和"冲动操作"隔开。

**再平衡规则（写入 IPS）**

- 触发方式：日历与阈值结合。每年固定检查一次，期间任一大类偏离目标超过设定阈值时触发。
- 执行顺序：先用新增资金和分红调整，再在递延税账户内调整，最后才在应税账户卖出。
- 战术调整只能在 M3 给定的偏离带内进行。

**交易前检查清单**

- [ ] 这笔交易符合 IPS 的投资范围和集中度限制
- [ ] 依据的数据是最新的，并已通过校验
- [ ] 已估算税务影响和交易成本
- [ ] 已写下证伪条件：什么情况说明这个决策错了
- [ ] 非紧急决策已等待至少一天
- [ ] 已记入决策日志

**决策日志模板**

```markdown
## 2026-10-22 | 决策：（例如：美国大盘股从 45% 下调至 40%）
- 触发来源：M2 / M4 / 再平衡阈值 / 生活变化
- 依据：关键数据及其日期和来源
- 预期：希望达到的效果
- 证伪条件：出现什么情况说明判断错误
- 复查日期：
- 事后结果（复查时填写）：
```

## L5 复盘与运行节奏

长期配置框架不需要每天看盘：月度做监控，季度做检查，年度做重设。年度更新放在 10 月到次年 1 月，正好接上摩根大通 LTCMA（10 月）和多家机构年度展望（12 月至 1 月）的发布时间。

| 频率 | 做什么 | 涉及模块 |
| --- | --- | --- |
| 每日 | 不需要操作 | — |
| 每周（自动） | 数据更新与校验；只有触发报警时才查看 | L1、L2、M6 |
| 每月 | 宏观体制判断、战术信号、风险监控，输出一页月报 | M1、M4、M6 |
| 每季 | 再平衡阈值检查；对照贝莱德、先锋的季度 CMA 检查自己的假设；季度归因；复查到期的决策日志 | M2、M6、M7、L4 |
| 每年 11–12 月 | 更新自己的 CMA，与机构 CMA 对标 | M2 |
| 每年 1 月 | 复审 IPS；重新做战略配置；年度归因；复核数据源注册表，替换失效来源 | L0、M3、M7、L1 |

## 可靠性与可扩展性设计

可扩展性靠三张注册表（资产、数据源、IPS）加一个统一的适配器接口实现：新增市场、数据源或模块时只加配置或文件，不改已有代码。可靠性靠主备双源、不可变快照和失败降级三项机制实现。

**数据源适配器接口**：每个来源实现同一个接口，输出同一种长表。

```python
class SourceAdapter(Protocol):
    name: str    # 与 sources.yaml 中的名称一致
    grade: str   # A / B / C / D
    def fetch(self, series_id: str, start: date, end: date) -> pd.DataFrame:
        """返回统一长表：date, series_id, value, unit, source, fetched_at"""
```

**数据源注册表示例**（`sources.yaml`）

```yaml
us_10y_yield:
  primary: {adapter: treasury, id: "10 Yr"}
  backup:  {adapter: fred, id: DGS10}
  unit: percent
  freq: daily
  max_diff: 0.02   # 主备源允许的最大偏差（百分点），超过则报警
```

**资产注册表示例**（`assets.yaml`，代码仅为示例）

```yaml
- id: us_large_cap
  class: equity
  market: US
  currency: USD
  benchmark: "S&P 500"
  vehicles: [VOO, IVV]          # 实现工具，可多个
  cma_method: grinold_kroner     # M2 使用的估算方法
  valuation_series: [shiller_cape, damodaran_erp]
```

**扩展方式**

| 要扩展的内容 | 需要做的事 |
| --- | --- |
| 新增一个市场（例如日本） | 在 `assets.yaml` 加条目；如有新数据源，写一个适配器 |
| 新增一个数据源 | 写适配器，并在 `sources.yaml` 登记等级和备用源 |
| 新增一个分析模块 | 在 `modules/` 加文件，读取标准长表，输出标准结果表 |
| 从表格版升级到代码版 | 表格中的工作表一一对应三张注册表和模块输出，逐个迁移 |

**可靠性机制**

1. **主备双源**：关键序列都有备用来源，偏差超过阈值时报警，由人判断，不自动选择。
2. **不可变快照**：原始数据按抓取日期保存，绝不覆盖；宏观数据保留修订版本。
3. **失败降级**：主源失败时切换备用源；都失败时使用最近缓存，并在报告上标注"数据陈旧"及其日期。
4. **等级约束**：D 级来源的数据不能单独触发任何交易决策。
5. **可追溯**：每份报告的页脚打印数据截止日期和代码版本号。

分四个阶段推进，每个阶段有明确的通过条件；没有通过就不进入下一阶段，以免工具的复杂度跑在决策需要的前面。

阶段 1 只需要一个表格就能开始做决策；代码化从阶段 2 开始，而且只替代已经在表格里跑通的部分。

**已知风险与局限**

- **免费行情不稳定**：yfinance 频繁限流，AKShare 依赖网页结构，任何一次改版都可能中断。对策是双源、缓存和失败降级。
- **存活偏差与复权**：免费数据大多只覆盖现存证券，回测结果会偏乐观；不同来源的复权方式也不一致。
- **数据修订与口径变化**：美国宏观数据会修订，中国社融等指标口径多次调整。对策是保留数据版本。
- **模型风险**：CMA 对假设高度敏感，优化器会放大输入误差。对策是用区间、约束和敏感性分析。
- **免费条款会变**：例如 FRED 在 2025 年底收紧了程序化访问。数据源注册表需要每年复核。
- **过度工程**：最常见的失败是系统越建越复杂，而决策质量没有提高。每增加一个模块，先问它服务哪个决策。

本框架是分析工具的设计，不构成投资、税务或法律建议。
