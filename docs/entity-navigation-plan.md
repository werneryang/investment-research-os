# 主体与产业关系浏览实施计划

日期：2026-10-31。依据用户确认的通用公司关系方案。状态：实现与本地交互验证完成。

## 目标与范围

在现有「对象 × 问题」框架内增加具体公司/主体定位；公司页与数据参照页共用索引及关系展示。所有入口按已有证据组织，不按报告中出现的名称推断研究归属。本次不新增研究计算、供应关系或复核结论，不代替芯片研究的公开归档。

## 修改步骤

1. **统一主体索引**：读取既有主体、业务、分部映射、关系与证据；以登记 ID 为主，有 CIK 时与公司研究样本精确合并。公司名称/中文名/简称/代码只作检索别名。网站显式登记研究主体，未知主体与冲突标识构建失败。
2. **查找与关系查看**：首页和能力地图增加具体主体选择、名称搜索建议及明确的选择动作；错拼仅建议，不自动改选。数据与参照页增加主体、业务、关系类型、证据申报日期及技术状态筛选，支持 URL、语言切换和无脚本阅读。公司页嵌入自身业务与直接关系，任何对手方都能回到同一参照视图继续查找。
3. **证据与探索**：逐行展示方向、产品/服务、业务无法确定原因、占比的完整口径、申报日期和未知有效期；对象及证据的技术记录与人工状态分别显示。增加两家公司关系记录对照及可选的一跳关系示意；表与图使用同一筛选集合，不推导传递关系、不比较未披露的经济权重。
4. **验证与发布**：验证双向查找一致、反向角色正确、没有研究页的主体可访问、未知/空主体不假装存在、匿名主体不合并、缺失证据日期不通过日期筛选、失效复核不呈现为通过、活动不明不归类、股东/客户比例不混用。检查中文/英文、移动布局、无脚本内容、直接链接及浏览器前进后退。功能分支验证后提交推送、合并 main、运行全套 pytest、自动发布并核对实际线上版本。

## 交付边界

- 无记录表示「尚未收录」，不是「确认不存在」。已登记主体、关联研究、当前可访问结果分别计数。
- 证券代码不充当历史证券身份；别名不产生证券估值入口。
- 日期筛选限定证据的申报日期，不证明关系在该日有效或当时可交易。
- 当前构建只核对技术记录指纹，不冒充重新下载、原文机器核验或人工签认。
- 候选、失效、被否定与撤回记录都保留可追溯状态；关系示意不将候选画成已确认事实。
